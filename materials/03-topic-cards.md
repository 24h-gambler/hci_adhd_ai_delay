# 03 · 주제 안내 카드 2종

**시점**: 각 블록의 첫 대화 직전 (블록당 1회)
**형식**: A5 카드 1장 + 화면에도 동일 문구 표시
**원칙**: **범위는 정하되 내용은 자유.**

| 너무 좁으면 | 너무 넓으면 |
| --- | --- |
| 인위적이고 몰입이 안 된다 | 참가자마다 대화가 완전히 달라져 비교가 안 된다 |

---

## 0. 두 카드에 공통으로 적용되는 형식 제약

두 맥락의 카드는 **읽는 부담이 같아야 한다.** 한쪽이 길면 그 자체가
조건 차이가 된다.

| 항목 | 규격 |
| --- | --- |
| 본문 글자 수 | 각 90 ~ 110자 (공백 포함) |
| 문장 수 | 각 3문장 |
| 예시 목록 | 각 4개 |
| 하단 고지 | 두 카드 동일 문구 |

카드를 수정할 때마다 글자 수를 다시 센다.
→ `analysis/manipulation_check.py`가 카드 길이를 검사하지는 않으므로 수동 확인.

## 1. 맥락 A · 일상 대화 카드

```
────────────────────────────────────────────
  대화 주제 · 이번 묶음

  최근에 보신 영화, 드라마, 유튜브, 책 같은
  콘텐츠에 대해 AI와 이야기를 나눠 보세요.
  무엇이든 편하게 말씀하시면 됩니다.

  ── 떠오르지 않으시면 ──────────────
   · 최근에 끝까지 본 것
   · 보다가 그만둔 것
   · 누군가에게 추천했던 것
   · 남들은 좋다는데 나는 별로였던 것

  ── 안내 ─────────────────────────
   이 대화는 다섯 번 주고받으면 마무리됩니다.
   언제든 "그만하겠습니다"라고 하시면 멈춥니다.
────────────────────────────────────────────
```

**설계 근거**
- 정서적 부담이 낮으면서 **할 말은 확실히 있는** 주제다.
- "떠오르지 않으시면" 목록은 **막힘(stalling) 방지용**이다. ADHD 경향
  참가자에게 열린 질문만 주면 시작 자체가 부담이 될 수 있고, 대화가
  막히면 그 좌절이 지연 평가에 섞인다.
- 4개 항목은 **회상 단서**이지 선택지가 아니다. 카드에 "골라서"라고 쓰지 않는다.

## 2. 맥락 B · 고민 상담 카드

```
────────────────────────────────────────────
  대화 주제 · 이번 묶음

  요즘 신경 쓰이거나 마음에 걸리는 일에 대해
  AI와 이야기를 나눠 보세요.
  말씀하고 싶은 만큼만 말씀하시면 됩니다.

  ── 떠오르지 않으시면 ──────────────
   · 요즘 미뤄 두고 있는 일
   · 결정을 못 내리고 있는 일
   · 반복해서 신경 쓰이는 관계
   · 시간이나 계획대로 잘 안 되는 일

  ── 안내 ─────────────────────────
   이 대화는 다섯 번 주고받으면 마무리됩니다.
   불편하시면 언제든 멈추실 수 있습니다.
   앞서 안내드린 주제는 다루지 않습니다.
────────────────────────────────────────────
```

**설계 근거**
- **중단 권리를 카드에 명시**한다. 구두 안내만으로는 부족하고, IRB 요건이다.
  참가자가 카드를 계속 보고 있으므로 가장 확실한 고지 위치다.
- 하단 3행에 **배제 주제를 다시 상기**시킨다. 다만 목록을 반복하지 않는다.
  카드에 자해·자살을 다시 나열하면 그 자체가 주제를 활성화한다.
  (배제 목록 전문은 `02-participant-briefing.md §3`과 인쇄물에 있다.)
- 예시 4개는 **ADHD 경향 참가자에게 실제로 잘 걸리는 영역**으로 골랐다
  (미루기 · 의사결정 · 관계 · 시간 관리). 동시에 임상적 범위 밖이다.
  ⚠️ 이 선택이 집단 간 대화 내용을 체계적으로 다르게 만들 수 있다 →
  `OPEN_QUESTIONS.md` Q3.

## 3. 카드 제시 절차

1. 연구자가 카드를 책상에 놓는다.
2. **연구자는 카드를 읽어 주지 않는다.** 참가자가 직접 읽는다.
   구두로 덧붙이면 참가자마다 받는 정보가 달라진다.
3. 참가자가 다 읽었다고 하면 화면의 시작 버튼을 누르게 한다.
4. 카드는 **블록 내내 책상에 둔다.** 대화 3개 동안 계속 참조할 수 있다.
5. 참가자가 "무슨 말을 해야 할지 모르겠다"고 하면 고정 응답:

   > "카드에 적힌 범위 안이면 뭐든 괜찮습니다. 편한 대로 시작해 보세요."

   그 이상 예시를 들어 주지 않는다.

## 4. 턴 수 고정과 진행 표시

**대화 1개 = 5턴** (사용자 발화 5회 / AI 응답 5회) 후 자동 종료.

### 화면 표시

```
  이번 대화는 5번 주고받으면 마무리됩니다.  (2 / 5)
```

- 참가자가 언제 끝나는지 알 수 있어야 **"끝날 때까지 버티는" 태도가 아니라
  자연스러운 대화**가 된다.
- 카운터는 **사용자가 전송한 직후에** 증가시킨다. AI 응답이 표시되는
  시점에 증가시키면 지연 구간에서 카운터가 멈춰 있는 것이 보이고,
  그게 대기 시간의 시각적 단서가 된다.

### ⚠️ 판단이 필요한 지점

진행 표시를 보여주면 **남은 분량을 알게 되고**, 그것이 시간 경험에
영향을 줄 수 있다 (특히 "긺" 조건에서 "아직 세 번 더 남았네"는
지연 지각을 증폭시킬 수 있다).

→ 파일럿에서 확인. `OPEN_QUESTIONS.md` Q4.

### ⚠️ 함께 결정해야 하는 것 — 지연 구간의 화면 상태

턴 수 표시보다 **훨씬 결정적인 변수인데 아직 정해지지 않았다.**
AI 응답을 기다리는 D초 동안 화면에 무엇이 보이는가?

| 안 | 내용 | 문제 |
| --- | --- | --- |
| (a) 아무 표시 없음 | 빈 화면 | 고장으로 오해할 수 있음. 16~20초는 매우 길다 |
| (b) 정적 표시 | "…" 고정 | 무난하나 진행감이 없음 |
| (c) 타이핑 인디케이터 | 점 3개 애니메이션 | 실제 챗봇과 가장 유사 |
| (d) 진행 바 | 남은 시간 시각화 | **금지** — 지연을 명시적 정보로 만든다 |

- (d)는 배제한다. 시스템 프롬프트 원칙 4(지연을 언급하지 않는다)와
  같은 이유에서, 화면도 지연을 명시해서는 안 된다.
- (a)~(c) 중 무엇을 쓰든 **세 조건에서 완전히 동일해야 한다.**
- 어느 쪽이든 논문에 그림으로 보고해야 재현이 가능하다.
