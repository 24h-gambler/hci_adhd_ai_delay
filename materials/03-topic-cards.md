# 03 · 주제 안내 카드 2종

**시점**: 각 블록의 첫 대화 직전 (블록당 1회)
**형식**: A5 카드 1장 + 화면에도 동일 문구 표시
**원칙**: **범위는 정하되 내용은 자유.**

| 너무 좁으면 | 너무 넓으면 |
| --- | --- |
| 인위적이고 몰입이 안 된다 | 참가자마다 대화가 완전히 달라져 비교가 안 된다 |

---

## 1. 맥락 A · 일상 대화

```
────────────────────────────────────────────
  이번에는 이런 이야기를 해 주세요

  최근에 보신 영화, 드라마, 영상 같은
  콘텐츠에 대해 이야기해 주세요.

  무엇이든 편하게 말씀하시면 됩니다.

  5번 주고받으면 이 대화는 마무리됩니다.
────────────────────────────────────────────
```

정서적 부담이 낮으면서 **할 말은 확실히 있는** 주제다.
관여를 유발하려는 조건이 아니라 **대조 조건**이다.

---

## 2. 맥락 B · 고민 상담

```
────────────────────────────────────────────
  이번에는 이런 이야기를 해 주세요

  요즘 실제로 신경 쓰이거나 마음에 걸리는 일에 대해
  이야기해 주세요.

  지어낸 이야기가 아니라 실제 고민일 때
  연구에 도움이 됩니다.

  말씀하고 싶은 만큼만 하시면 되고,
  불편하시면 언제든 멈추실 수 있습니다.

  5번 주고받으면 이 대화는 마무리됩니다.
────────────────────────────────────────────
```

### ★ "실제"를 두 번 강조하는 이유 — 이 카드가 관여의 출처다

명세서 §3:

> 관여는 AI의 말투가 아니라 참가자 자신의 주제에서 나와야 한다. AI가
> 따뜻하게 말하면 참가자는 그 말에 반응하게 되고, 그러면 "이 AI가 나를
> 신경 쓴다"고 느꼈을 때 **16초 때문인지 그 말 때문인지 구별할 수 없다.**
> Nass가 얼굴과 목소리를 없앤 것과 같은 이유다.

**따라서 관여 확보의 책임을 주제 안내가 진다.**

```
파일럿에서 관여 지수가 낮게 나오면
  ✗ AI의 공감 표현을 올린다        ← 하면 안 된다
  ✓ 이 카드의 문구를 강화한다
```

→ `materials/06 §다`, `materials/04 §4`

### 중단 권리를 카드에 명시한다

IRB 요건이다. 동의서에서 한 번 안내했더라도 **실제로 부담이 생기는 시점에
다시 보이는 것**이 중요하다.

### 두 카드의 길이가 다른 것

맥락 B 카드가 길다. "실제" 강조 두 줄과 중단 권리 문구 때문이며,
둘 다 뺄 수 없다. 읽는 시간 차이는 대화 3개(15턴)에 걸쳐 희석된다.

**배제 주제 목록은 카드에 반복하지 않는다.** 카드에 자해·자살을 다시
나열하면 그 자체가 주제를 활성화한다. 전문은 사전 안내문에 있다.

---

## 3. 카드 제시 절차

1. 연구자가 카드를 책상에 놓는다.
2. **연구자는 카드를 읽어 주지 않는다.** 참가자가 직접 읽는다.
   구두로 덧붙이면 참가자마다 받는 정보가 달라진다.
3. 참가자가 다 읽었다고 하면 화면의 시작 버튼을 누르게 한다.
4. 카드는 **블록 내내 책상에 둔다.** 대화 3개 동안 계속 참조할 수 있다.

### 참가자가 막혔을 때 — 연구자 고정 응답

> "카드에 적힌 범위 안이면 뭐든 괜찮습니다. 편한 대로 시작해 보세요."

**그 이상 예시를 들어 주지 않는다.** 예시를 즉흥적으로 주면
참가자마다 대화 내용이 체계적으로 달라진다.

### ⚠️ 막힘이 반복되면 — 예시 블록 추가 (파일럿에서 판단)

ADHD 경향 참가자에게 열린 질문만 주면 **시작 자체가 부담**이 될 수 있고,
대화가 막히면 그 좌절이 지연 평가에 섞인다.
파일럿에서 막힘이 반복되면 아래를 **두 카드에 대칭으로** 추가한다.

```
【맥락 A에 추가】              【맥락 B에 추가】
 떠오르지 않으시면              떠오르지 않으시면
  · 최근에 끝까지 본 것          · 요즘 미뤄 두고 있는 일
  · 보다가 그만둔 것             · 결정을 못 내리고 있는 일
  · 누군가에게 추천했던 것        · 반복해서 신경 쓰이는 관계
  · 남들은 좋다는데 별로였던 것   · 시간이나 계획대로 잘 안 되는 일
```

- 한쪽에만 넣으면 안 된다. **넣으려면 양쪽 다.**
- 맥락 B의 예시는 ADHD 경향 참가자에게 잘 걸리는 영역이라
  집단 간 대화 내용을 체계적으로 다르게 만들 수 있다 →
  `OPEN_QUESTIONS.md` Q3.

## 4. 턴 수 고정과 진행 표시

**대화 1개 = 5턴** (사용자 발화 5회 / AI 응답 5회) 후 자동 종료.

### 화면 표시

```
  이번 대화는 5번 주고받으면 마무리됩니다.  (2 / 5)
```

- 참가자가 언제 끝나는지 알 수 있어야 **"끝날 때까지 버티는" 태도가 아니라
  자연스러운 대화**가 된다.
- 카운터는 **사용자가 전송한 직후에** 증가시킨다. AI 응답이 표시되는
  시점에 증가시키면 지연 구간에서 카운터가 멈춰 있는 것이 보이고,
  그게 대기 시간의 시각적 단서가 된다.

### ⚠️ 판단이 필요한 지점

진행 표시를 보여주면 **남은 분량을 알게 되고**, 그것이 시간 경험에
영향을 줄 수 있다 (특히 긺 조건에서 "아직 세 번 더 남았네"는
지연 지각을 증폭시킬 수 있다).

→ 파일럿에서 확인. `OPEN_QUESTIONS.md` Q4.

### ★ 응답 대기 표시 — 아무것도 표시하지 않는다 (명세서 §4에서 확정)

```
앱 기본값: ?indicator=none
```

명세서:

> 점 세 개나 "입력 중" 같은 표시는 **그 자체가 사회적 단서**이며 지연
> 효과와 섞인다. 빈 화면으로 두는 것이 조작을 순수하게 유지한다.
> 실제 챗봇은 대부분 "생각 중" 표시를 보여주지만, 그것을 넣으면 **지연이
> 무엇을 뜻하는지를 시스템이 알려주는 셈**이 된다. 이 연구는 참가자가
> **아무 단서 없이 침묵을 어떻게 읽는가**를 본다.

`…` 하나도 "무언가 하고 있다"는 신호라 M1(기술적 귀인)과 M3(사회적 귀인)를
모두 흔든다. **논문에 이 결정을 명시한다.**

앱에는 `?indicator=dots|typing`이 남아 있으나 **파일럿 비교용이며 본 실험에서
쓰지 않는다.** 진행 바는 어느 경우에도 금지한다.

### 대화 종료 (명세서 §4)

`"이번 대화가 끝났습니다"`를 **2초간 표시한 뒤 자동으로** 문항 화면으로
전환한다. 버튼을 누르게 하지 않는다 — 갑자기 바뀌면 대화의 여운이 끊긴다.

### 블록 전환 (명세서 §4)

> "잠시 다른 활동을 하겠습니다"

**"이제 다른 주제로 가겠습니다"라고 하면 안 된다.** 맥락 조작을 드러낸다.
