# 03 · 주제 안내 카드 2종

**시점**: 각 블록의 첫 대화 직전 (블록당 1회)
**형식**: A5 카드 1장 + 화면에도 동일 문구 표시
**원칙**: **범위는 정하되 내용은 자유.**

| 너무 좁으면 | 너무 넓으면 |
| --- | --- |
| 인위적이고 몰입이 안 된다 | 참가자마다 대화가 완전히 달라져 비교가 안 된다 |

---

## 1. 맥락 A · 일상 대화

```
────────────────────────────────────────────
  대화 주제

  최근에 보신 영화, 드라마, 영상 같은
  콘텐츠에 대해 이야기해보세요.
  무엇이든 편하게 말씀하시면 됩니다.

  5번 주고받으면 이 대화는 마무리됩니다.
────────────────────────────────────────────
```

정서적 부담이 낮으면서 **할 말은 확실히 있는** 주제다.

---

## 2. 맥락 B · 고민 상담

```
────────────────────────────────────────────
  대화 주제

  요즘 신경 쓰이거나 마음에 걸리는 일에 대해
  이야기해보세요.

  말씀하고 싶은 만큼만 하시면 되고,
  불편하시면 언제든 멈추실 수 있습니다.

  5번 주고받으면 이 대화는 마무리됩니다.
────────────────────────────────────────────
```

**중단 권리를 카드에 명시한다 — IRB 요건.**
구두 안내만으로는 부족하다. 참가자가 카드를 계속 보고 있으므로
가장 확실한 고지 위치다.

### 두 카드의 길이가 다른 것에 대하여

맥락 B 카드가 한 줄 길다. 중단 권리 문구 때문이다.
안내문 길이가 다르면 읽는 시간이 달라져 그 자체가 조건 차이가 되지만,
**이 경우는 감수한다.** 중단 권리 고지는 뺄 수 없고, 한 줄 차이가
만드는 읽기 시간 차이는 대화 3개(15턴)에 걸쳐 희석된다.

대신 아래는 지킨다.

- 두 카드의 **본문 구조를 같게** 유지한다 (주제 → 자유도 → 턴 수).
- 카드를 수정할 때 한쪽만 길어지지 않게 한다.
- **배제 주제 목록을 카드에 반복하지 않는다.** 카드에 자해·자살을
  다시 나열하면 그 자체가 주제를 활성화한다. 전문은 사전 안내문에 있다.

---

## 3. 카드 제시 절차

1. 연구자가 카드를 책상에 놓는다.
2. **연구자는 카드를 읽어 주지 않는다.** 참가자가 직접 읽는다.
   구두로 덧붙이면 참가자마다 받는 정보가 달라진다.
3. 참가자가 다 읽었다고 하면 화면의 시작 버튼을 누르게 한다.
4. 카드는 **블록 내내 책상에 둔다.** 대화 3개 동안 계속 참조할 수 있다.

### 참가자가 막혔을 때 — 연구자 고정 응답

> "카드에 적힌 범위 안이면 뭐든 괜찮습니다. 편한 대로 시작해 보세요."

**그 이상 예시를 들어 주지 않는다.** 예시를 즉흥적으로 주면
참가자마다 대화 내용이 체계적으로 달라진다.

### ⚠️ 막힘이 반복되면 — 예시 블록 추가 (파일럿에서 판단)

ADHD 경향 참가자에게 열린 질문만 주면 **시작 자체가 부담**이 될 수 있고,
대화가 막히면 그 좌절이 지연 평가에 섞인다.
파일럿에서 막힘이 반복되면 아래를 **두 카드에 대칭으로** 추가한다.

```
【맥락 A에 추가】              【맥락 B에 추가】
 떠오르지 않으시면              떠오르지 않으시면
  · 최근에 끝까지 본 것          · 요즘 미뤄 두고 있는 일
  · 보다가 그만둔 것             · 결정을 못 내리고 있는 일
  · 누군가에게 추천했던 것        · 반복해서 신경 쓰이는 관계
  · 남들은 좋다는데 별로였던 것   · 시간이나 계획대로 잘 안 되는 일
```

- 한쪽에만 넣으면 안 된다. **넣으려면 양쪽 다.**
- 맥락 B의 예시는 ADHD 경향 참가자에게 잘 걸리는 영역이라
  집단 간 대화 내용을 체계적으로 다르게 만들 수 있다 →
  `OPEN_QUESTIONS.md` Q3.

## 4. 턴 수 고정과 진행 표시

**대화 1개 = 5턴** (사용자 발화 5회 / AI 응답 5회) 후 자동 종료.

### 화면 표시

```
  이번 대화는 5번 주고받으면 마무리됩니다.  (2 / 5)
```

- 참가자가 언제 끝나는지 알 수 있어야 **"끝날 때까지 버티는" 태도가 아니라
  자연스러운 대화**가 된다.
- 카운터는 **사용자가 전송한 직후에** 증가시킨다. AI 응답이 표시되는
  시점에 증가시키면 지연 구간에서 카운터가 멈춰 있는 것이 보이고,
  그게 대기 시간의 시각적 단서가 된다.

### ⚠️ 판단이 필요한 지점

진행 표시를 보여주면 **남은 분량을 알게 되고**, 그것이 시간 경험에
영향을 줄 수 있다 (특히 긺 조건에서 "아직 세 번 더 남았네"는
지연 지각을 증폭시킬 수 있다).

→ 파일럿에서 확인. `OPEN_QUESTIONS.md` Q4.

### ⚠️ 아직 정해지지 않은 것 — 지연 구간의 화면 상태

턴 수 표시보다 **훨씬 결정적인 변수다.**
AI 응답을 기다리는 D초 동안 화면에 무엇이 보이는가?

| 안 | 내용 | 문제 |
| --- | --- | --- |
| (a) 아무 표시 없음 | 빈 화면 | 고장으로 오해할 수 있음. 16~20초는 매우 길다 |
| (b) 정적 표시 | "…" 고정 | 무난하나 진행감이 없음 |
| (c) 타이핑 인디케이터 | 점 3개 애니메이션 | 실제 챗봇과 가장 유사 |
| (d) 진행 바 | 남은 시간 시각화 | **금지** — 지연을 명시적 정보로 만든다 |

- (d)는 배제한다. 프롬프트에서 지연을 언급하지 못하게 한 것과 같은
  이유로, 화면도 지연을 명시해서는 안 된다.
- (a)~(c) 중 무엇을 쓰든 **세 조건에서 완전히 동일해야 한다.**
- (c)는 "AI가 생각하고 있다"는 귀인을 유도할 수 있다. 귀인이 인터뷰의
  관심사이므로(`07 §F`), 중립적인 쪽이 나을 수 있다.
- 어느 쪽이든 논문에 화면 그림으로 보고해야 재현이 가능하다.
