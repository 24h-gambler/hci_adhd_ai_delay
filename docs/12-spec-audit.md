## §0 · 전 화면 표기 규칙

명세서는 금지어 표를 둔다. **참가자에게 보이는 모든 문구에 적용된다.**

| 금지 | 대신 | 저장소 상태 |
| --- | --- | --- |
| 지연·대기·기다림·느림·빠름 | 응답 시간 · 답이 나타나기까지 | ✅ 위반 없음 |
| **상대 · 그 · 그녀 · 파트너** | **AI · 이 대화** | 🔴 **5곳 위반** |
| 설정·조정·실험 조건 | — | ✅ |
| **평균 · 전체적으로** | **대체로** | 🔴 **2곳 위반** |
| 답답·짜증·불쾌 등 정서어 | 불편 (중립어) | ✅ |
| 정답·올바른·정확한 | — | ✅ |

### 🔴 A. "상대"가 M3를 유도한다 — 가장 심각

```
app/static/index.html:211  "메시지를 보낸 뒤 상대의 답이 …"
app/static/index.html:229  "방금 대화 상대에 대해 …"
app/static/index.html:239  "방금 대화 상대에 대한 인상을 …"
materials/05:17, 05:93
```

명세서의 근거를 그대로 옮기면:

> "상대"는 사회적 존재로 미리 규정한다. **M3(사회적 귀인)를 유도하므로
> 그 문항이 잡으려는 것을 문항이 만들어버린다.**

이 연구의 핵심 판정은 **M3∧M4**(설계를 알면서도 사회적으로 반응)다.
그 M3를 문항이 먼저 심어 주면 판정 자체가 성립하지 않는다.
Godspeed(의인화) 문항에서 "상대"라고 부르는 것은 특히 나쁘다 —
재려는 구성개념을 문항이 지시하고 있다.

**→ 전부 "AI"로 교체한다.**

### 🔴 B. "평균"이 인지 부담을 만든다

명세서: 평균을 내려면 여러 차례를 기억해 계산해야 한다. 인지 부담이 크고
정확도도 낮다 → **"대체로"**.

ADHD 성인 대상 연구에서 작업기억 부담을 주는 문항은 특히 문제가 된다.

**→ "대체로"로 교체한다.**

## §1 · 대화 직후 문항 — 3개 · 6회 · 20초 안

| 명세서 | 저장소 | |
| --- | --- | --- |
| ① 시간 추정 (AI · 대체로 · 모르겠음) | 문구 위반 | 🔴 |
| ② 불편감 7점 | 일치 | ✅ |
| **③ 한 단어** | **없음** | 🔴 |
| PETS · Godspeed는 **여기 없음** | 여기 있음 | 🟠 |
| 20초 안에 끝날 것 | 13문항이라 불가능 | 🟠 |

### 🔴 C. "한 단어" 문항이 통째로 빠져 있다

```
③ 방금 대화를 한 단어로 표현한다면 무엇인가요?
   [________]  떠오르는 대로 적어 주세요. 어떤 단어든 괜찮습니다.
```

명세서가 두 가지 역할을 준다.

1. **Holmberg 직접 비교** — Holmberg가 "정확히 다섯 단어로 요약"을 시켰고
   ADHD 참가자가 음성 조건에서 기계적 서술어를 더 썼다. 한 단어로 줄여
   부담을 낮추되 비교 가능하게 했다.
2. **인터뷰 회상 단서** — "이 대화는 '차분'이라고 쓰셨네요. 어떤 점에서
   그러셨어요?"로 바로 들어간다.

내 인터뷰 가이드는 회상 단서로 **시간 추정치**를 쓰고 있었다.
명세서는 한 단어를 쓴다. 한 단어가 훨씬 낫다 — 시간 추정치를 되짚으면
그 자체가 응답 시간에 주의를 다시 준다.

**"어떤 단어든 괜찮습니다"가 빠지면 안 된다.** 없으면 참가자가
"옳은 단어"를 찾으려 든다.

### 🟠 D. PETS · Godspeed의 위치가 다르다

명세서: **블록 종료 문항(2회)**. 저장소: 대화 직후(6회).

6회 반복은 명세서의 "20초 안" 제약을 깨고, 축약형을 강요하며,
반복 노출로 반응이 굳는다. 2회면 축약할 이유도 줄어든다.

**→ 블록 종료로 옮긴다.** `OPEN_QUESTIONS.md` Q8(PETS 축약)의 전제가 바뀐다.

## §2 · 블록 종료 문항 — 2회

### 2-1 PETS 축약형 · Godspeed I

| 명세서 | 저장소 | |
| --- | --- | --- |
| Godspeed I를 **1–5점**으로 (Holmberg와 동일) | 1–5점 | ✅ |
| Godspeed 5문항 유지 | 5번 문항 제외를 권고했었음 | 🟡 |
| 자리표시자 → 본 실험 전 원문 교체 | 자리표시자 명시 | ✅ |

🟡 내 `materials/05 §④`는 Godspeed 5번(*Moving rigidly–elegantly*)이
텍스트 챗봇에 안 맞으니 4문항으로 줄이자고 권고했다. 명세서는
**Holmberg와 같은 척도·같은 점수 범위**를 쓴다고 못박았다.
직접 비교가 목적이면 명세서가 맞다. **권고를 철회하고 5문항을 유지한다.**

### 2-2 관여 지수 — 🟠 구조가 다르다

| | 명세서 | 저장소 |
| --- | --- | --- |
| 문항 수 | 4 | 5 |
| 척도 | **1–5** | 1–7 |
| 실시 블록 | **고민 상담 블록만** | 양 블록 |
| ④ 자기개방 | **역방향 채점** | 역방향 아님 |
| 자유 기입 | 없음 | 있음 |
| 목적 | **측정된 조절변인** (담화 대조용) | 맥락 조작 점검 |

**목적이 다르다.** 내 `materials/06`은 이것을 맥락 조작 점검으로 보고
"맥락 A에서도 재야 비교 기준이 생긴다"고 썼다. 명세서는 관여 지수를
**참가자를 관여 높음·낮음으로 나눠 담화를 대조하기 위한** 측정된 조절변인으로
쓴다. 그러면 A 블록 측정이 필요 없고, 명세서의 판단이 맞다.

명세서 문항 그대로:

```
① 방금 이야기한 내용은 실제로 요즘 신경 쓰이는 일이었나요?
   전혀 아니다 ①─②─③─④─⑤ 실제 고민이었다
② 그 일이 요즘 얼마나 신경 쓰이나요?
③ 이야기하는 동안 그 일에 대해 얼마나 집중하셨나요?
④ 평소에 이 이야기를 다른 사람에게 하시는 편인가요?   ← 역방향
   자주 한다 ①─②─③─④─⑤ 거의 하지 않는다
```

**대가**: 맥락 조작이 통했음을 수치로 보일 수 없다. 질적 대조가 그 역할을
대신한다는 것이 명세서의 입장이며, 논문 한계에 적어야 한다.

## §3 · 주제 안내 카드 — 🔴 관여 확보 논리가 정반대다

### 문구 차이

| | 명세서 | 저장소 |
| --- | --- | --- |
| 제목 | 이번에는 이런 이야기를 해 주세요 | 대화 주제 |
| 일상 | …이야기해 **주세요** | …이야기해**보세요** |
| 고민 | 요즘 **실제로** 신경 쓰이거나… | "실제로" 없음 |
| 고민 | **"지어낸 이야기가 아니라 실제 고민일 때 연구에 도움이 됩니다."** | **줄 자체가 없음** |

### 🔴 E. 관여가 낮을 때 무엇을 올리는가

명세서:

> 관여는 AI의 말투가 아니라 참가자 자신의 주제에서 나와야 한다. AI가
> 따뜻하게 말하면 참가자는 그 말에 반응하게 되고, 그러면 "이 AI가 나를
> 신경 쓴다"고 느꼈을 때 **16초 때문인지 그 말 때문인지 구별할 수 없다.**
> Nass가 얼굴과 목소리를 없앤 것과 같은 이유다.
>
> 파일럿에서 관여 지수가 낮게 나오면 **AI의 공감 표현을 올리는 것이
> 아니라 이 카드의 문구를 강화한다.**

내 `materials/04 §4`의 판정 규칙은 **정확히 반대**였다.

```
정서적 관여 문항이 맥락 A보다 유의하게 높지 않다 → B안 → C안   ← 틀렸다
```

공감 강도를 올리면 M3(사회적 귀인)가 AI의 말투에서 나오고, 그러면
이 연구가 주장하려는 "침묵이 사회적으로 읽힌다"가 무너진다.

**→ 판정 규칙을 뒤집는다. 관여가 낮으면 카드를 강화한다.**
A/B/C 세 안은 남기되 **상향 경로를 삭제**하고, 기본을 A(건조) 쪽으로
당길지 검토한다.

## §4 · 진행 표시와 종료 안내

| | 명세서 | 저장소 | |
| --- | --- | --- | --- |
| 차례 표시 | 상단에 `3 / 5` 형태 | 문장 + `(n / 5)` | 🟡 |
| **응답 대기 표시** | **아무것도 표시하지 않는다** | 기본값 `dots` (`…`) | 🔴 |
| 대화 종료 | "이번 대화가 끝났습니다" **2초** 후 자동 전환 | 버튼 클릭 | 🟠 |
| 블록 전환 | "잠시 다른 활동을 하겠습니다" | 확인 필요 | 🟡 |

### 🔴 F. 대기 표시를 넣으면 안 된다

명세서:

> 점 세 개나 "입력 중" 같은 표시는 **그 자체가 사회적 단서**이며 지연
> 효과와 섞인다. 빈 화면으로 두는 것이 조작을 순수하게 유지한다.
> 이 연구는 참가자가 **아무 단서 없이 침묵을 어떻게 읽는가**를 본다.

내 `OPEN_QUESTIONS.md` Q5는 이걸 "파일럿에서 결정"으로 열어 두고
기본값을 `dots`로 잡았다. **명세서가 이미 결정했고 근거도 더 낫다.**
`…` 하나도 "무언가 하고 있다"는 신호라 M1(기술적 귀인)과 M3를 모두 흔든다.

**→ 기본값을 `none`으로 바꾸고 Q5를 닫는다.** 논문에 이 결정을 명시한다.

## §5 · 인터뷰 — 🟠 구조가 통째로 다르다

| | 명세서 | 저장소 |
| --- | --- | --- |
| 구조 | 5단계 (도입2·개방4·회상8·대비8·귀인10 = 32분) | 2단계 + 중간 공개, 48분 |
| 공개 시점 | **없음 — 디브리핑은 세션 끝에 1회** | 인터뷰 중간에 공개 |
| 회상 화면 | 주제·시간추정·불편감·**한 단어**, **조건 미표시** | 로그 전체 공개 |
| 귀인 코드 | **M1~M8 · M3∧M4** | 없음 |
| 핵심 되묻기 | **있음** | 없음 |

### 🟠 G. 내 2단계 재구성은 없던 문제를 푼 것이었다

나는 "로그를 화면에 띄우면 조작이 드러난다"고 보고 인터뷰를 둘로 쪼개
중간에 공개하자고 제안했다(Q10). **명세서는 그 문제를 다르게 푼다 —
회상 화면에 조건을 표시하지 않는다.** 참가자 자신의 응답(주제·추정치·
불편감·한 단어)만 보여주면 공개 없이 회상이 된다.

명세서 쪽이 낫다. **내 2단계 구조를 폐기하고 5단계로 되돌린다.**
`OPEN_QUESTIONS.md` Q10을 그렇게 닫는다.

### 🔴 H. M1~M8 귀인 코드 체계가 통째로 빠져 있다

이 연구의 분석 골격인데 내 자료 어디에도 없다.

| 코드 | 참가자 발화 | 이어갈 말 |
| --- | --- | --- |
| M1 | "서버가 느렸겠죠" | "그렇게 생각하시니까 기다리는 게 어떠셨어요?" |
| M2 | "오래 걸린 만큼 답이 괜찮았어요" | "어떤 부분에서요?" "기다린 보람이 있으셨나요?" |
| M3 | "제 얘기를 생각해 준 것 같았어요" | "그렇게 느끼신 이유가 뭘까요?" |
| M4 | "그렇게 만들어 놓은 거겠죠" | 핵심 되묻기로 |
| M5 | 견딤 — 문항 ②와 대조 | |
| M7·M8 | 기다리는 동안 무엇을 했는가 | "기다리는 동안 뭘 하고 계셨어요?" |

**핵심 되묻기** (M4가 나온 뒤):

> "그렇게 생각하시면서도, 기다리는 동안에는 어떤 느낌이 드셨어요?"

이 한 문장이 **M3∧M4**를 만든다. 없으면 설계 인식에서 대화가 끝나
**CASA 판정이 불가능해진다.** 명세서는 이것이 약한 유도임을 인정하고
프로토콜을 논문에 공개해 독자가 판단하게 한다.

**→ 인터뷰 가이드를 명세서대로 다시 쓴다.**

## 여전히 남는 긴장 — 명세서 내부

### 문항 ① 6회 반복 vs §5-2 개방 단계

§5-2 ②의 임무:

> 참가자가 응답 시간을 **스스로 꺼내는지**, 몇 번째 발화에서 꺼내는지를
> 확인한다. 연구자는 속도·시간·기다림·느림을 **절대 먼저 말하지 않는다.**

그런데 §1 문항 ①이 **여섯 번** 응답 시간을 묻는다. 첫 대화 직후부터
"AI의 답이 나타나기까지 몇 초"를 묻고 나면, 개방 단계의 "자발적 언급"과
§7의 `탐지 여부: 자발적 언급 / 유도 후 언급 / 끝까지 언급 없음`은
사실상 전원 "자발적 언급"이 된다.

문항 ①이 독립적 관찰 대상이라는 명세서의 판단은 존중한다. 다만
**§7의 탐지 지표는 그 대가로 해석력을 잃는다.** 둘 중 하나다.

- 탐지 지표를 포기하고 §7에서 뺀다
- 문항 ①을 블록 종료로 옮긴다 (→ 시간 추정의 대화별 해상도를 잃는다)
- 그대로 두되 **"문항 ①에 노출된 뒤의 자발성"임을 논문에 명시**한다
