# A. 결과를 무효화할 수 있는 것

## 🔴 A1. 조건별 설문 문항 ①이 조작을 드러낸다

**이 검토에서 가장 심각한 항목이다.**

`docs/00 §4`의 절대 규칙 1번:

> 디브리핑 전까지 지연 조작을 어떤 자료에서도 암시하지 않는다.

그런데 `materials/05`의 문항 ①은 **첫 대화가 끝난 직후** 이렇게 묻는다.

> 메시지를 보낸 뒤 상대의 답이 화면에 나타나기까지
> 평균 몇 초쯤 걸렸다고 느끼셨나요?

이 문항은 조작된 변수를 이름 그대로 지목한다. 그리고 **6번 반복된다.**
대화 1이 끝난 시점에 모든 참가자가 "이 연구는 응답 시간에 관한 것"임을
알게 된다. 자료 두 개가 서로를 무너뜨린다.

무엇이 망가지는가.

| 대상 | 결과 |
| --- | --- |
| 대화 2~6의 불편감 · PETS · Godspeed | 지연을 **의식적으로 감시하는 상태**에서의 평정이 된다 |
| 인터뷰 C1~C4 자발적 언급 깔때기 (`materials/07`) | 조작 인지 지표로 설계했는데, 전원이 이미 안다 |
| 귀인 질문 (`materials/07 §F`) | "왜 늦었다고 생각했나"의 답이 이미 오염된다 |
| 순진한 측정 | **대화 1개뿐** — 사실상 참가자 간 설계 1셀 |

### 선택지

| 안 | 얻는 것 | 잃는 것 |
| --- | --- | --- |
| **① 블록 끝으로 이동** *(권고)* | 대화 1~3이 완전히 순진한 상태. 인지 여부가 블록 단위 요인이 되어 **모형에 넣을 수 있다** | 3개를 회상해서 답하므로 추정 오차가 커진다 |
| ② 참가자 간 분할 (절반만 매 대화 질문) | 문항의 반응성 자체를 측정 → 그 자체가 발견 | 필요 표본이 2배 |
| ③ 위장 (여러 속성 중 하나로) | 현저성 감소 | 완전히 없어지지는 않는다 |
| ④ 그대로 두고 재해석 | 변경 없음 | "순진한 관찰은 대화 1개"라고 논문에 써야 한다 |

**권고: ① + ③.** 블록의 세 대화가 끝난 직후, 세 대화를 나란히 놓고
**여러 속성을 함께** 묻는다 (대화 길이, 흐름, 답의 이해도, **답이 나타나기까지의
시간**). 시간만 단독으로 묻지 않으면 현저성이 크게 낮아진다.

이 배치의 부수 효과가 하나 있다. 블록 순서가 이미 상쇄되어 있으므로
**순진한 블록 / 인지된 블록이 맥락 A·B에 균형 있게 배분된다.**
"조작을 알게 되면 지연 경험이 어떻게 달라지는가"를 부수 결과로 얻는다.

→ `OPEN_QUESTIONS.md` Q19. **지도교수 확인 필요.**

## 🔴 A2. 시간 지각 기준선 측정이 없다

이 연구의 이론적 주장은 **ADHD의 시간 처리 특성**이 지연 경험을
다르게 만든다는 것이다. 그런데 자료 어디에도 **시간 지각 능력을 독립적으로
재는 과제가 없다.**

없으면 이렇게 반박당한다.

> 두 집단의 지연 평가가 다른 것은 알겠다. 그게 시간 처리 때문인지
> 좌절 내성, 주의 유지, 챗봇 사용 습관 때문인지 어떻게 아는가?

K-ASRS는 증상 자기보고이지 시간 지각 측정이 아니다.
설문 문항 ①은 **조작된 지연에 대한** 추정이라 독립 변인이 될 수 없다
(종속변인과 같은 자극에서 나온다).

**권고**: 세션 도입부(연습 턴 앞)에 **시간 재현 과제**를 3~5분 넣는다.
화면에 자극을 일정 시간 제시하고 같은 길이만큼 키를 누르게 하는 표준 과제로,
7·13·19초 구간을 각 3회 시행하면 충분하다. 그러면

- 개인별 **시간 재현 기울기·변산성**을 얻는다
- 그것과 지연 민감도의 상관을 볼 수 있다 → **"시간 처리 때문"이라는 주장이 검증 가능해진다**
- 집단 차이가 ASRS 점수가 아니라 시간 지각으로 매개되는지 볼 수 있다

⚠️ 지연을 암시하지 않도록 **"반응 시간 측정"이 아니라 "간단한 감각 과제"로
안내**하고, 실험 대화와 시각적으로 완전히 분리한다.

→ `OPEN_QUESTIONS.md` Q20.

## 🔴 A3. 표본 크기와 검정력 계획이 없다

자료 어디에도 목표 N이 없다. 그런데 N은 이미 두 곳에서 제약을 받고 있다.

| 요구 | 필요 턴 수 | 참가자 수 (30턴/인) |
| --- | --- | --- |
| 조작 점검 CI가 ±.10 안에 (r ≈ 0) | 388 | **13명** |
| 같은 조건, r = .03이면 | 790 | **27명** |

주 분석(지연 3수준 × 맥락 2 × 집단 2)의 검정력은 별도로 계산해야 하고,
**집단 × 지연 상호작용**이 관심사라면 주효과보다 훨씬 큰 N이 필요하다.

Q1(집단 구성)이 정해지지 않아 계산을 시작할 수 없다. **Q1 → 검정력 →
N 순서로 묶어서 정해야 한다.** 세션 1건이 90분 + 인터뷰 전사이므로
N은 실행 가능성 문제이기도 하다.

→ `OPEN_QUESTIONS.md` Q21.

# B. 잡음을 키우거나 해석을 좁히는 것

## 🟡 B1. 연습 턴이 모든 조건보다 빠르다

```
연습    800ms  고정
즉시    1000 ~ 2000ms
```

참가자의 **첫 경험이 어떤 조건보다도 빠르다.** 그 뒤 세 조건이 전부
기준선보다 느리게 느껴진다. `materials/02 §4`는 "참가자가 지연의 기준선을
갖게 되면 이후 조건 비교가 오염된다"고 스스로 적어 두고, 값은 가장 빠르게
잡았다.

**권고**: 연습 턴을 **중간 조건 범위(8~9초)**로 두거나, 그 참가자의 첫
대화 조건과 같은 범위에서 뽑는다. 어느 쪽이든 앵커가 중앙으로 간다.
연습 턴은 분석에서 빠지므로 통제상 비용이 없다.

## 🟡 B2. 고민 상담 블록이 서로 다른 고민 3개를 요구한다

한 블록에 대화가 3개이고 각 대화는 독립이다. 참가자는 **한자리에서 서로 다른
고민 3개**를 꺼내야 한다. 세 번째 고민은 첫 번째보다 얕을 수밖에 없다.

조건 순서가 상쇄되어 **편향은 아니지만 잡음이 크다.** 그리고 정서적 관여가
블록 안에서 단조 감소하면 `materials/06`의 맥락 조작 점검이 약해진다.

**권고**: 파일럿에서 **블록 내 대화 위치별 정서적 관여**를 확인한다.
감소가 뚜렷하면 맥락 B 블록을 2대화로 줄이는 것도 검토 대상이다
(그러면 설계가 불균형해지므로 대안 비교가 필요하다).

## 🟡 B3. 이탈이 설계상 측정 불가능하다

5턴 자동 종료라 **참가자가 그만둘 수 없다.** 그런데 긴 지연의 가장 중요한
실제 결과는 "떠난다"이다. 지금 설계로는 그것을 관찰할 수 없고,
`OPEN_QUESTIONS.md` Q14의 "긺 조건 이탈률"도 잴 수 없다.

**권고**: 대화 화면에 **"이 대화 마치기"** 버튼을 두고, 누른 시점과 턴을
기록한다. 5턴 고정은 유지하되(비교 가능성) 조기 종료를 **종속변인으로**
얻는다. 누른 참가자의 그 대화는 주 분석에서 빼고 이탈 지표로 따로 쓴다.

## 🟡 B4. 블록 2의 조건 순서가 블록 1로 완전히 결정된다

```
블록1 = PERMS[(n-1) % 6]
블록2 = PERMS[(n-1+3) % 6]
```

참가자 24명에서 나타나는 (블록1, 블록2) 순서 쌍은 **36가지 중 6가지뿐**이다.
두 블록의 순서가 완전히 상관되어 있어, 블록 × 순서 상호작용이 있다면
분리할 수 없다.

각 블록 안에서는 6순열이 모두 나타나므로 **1차 이월효과는 균형이 맞는다.**
치명적이지는 않다.

**권고**: 블록 2의 오프셋을 참가자 번호로 바꿔 쌍을 늘린다
(예: `PERMS[(n-1 + 1 + (n-1)//6) % 6]`). `app/schedule.py` 한 줄이고
`test_schedule.py`의 "두 블록 순서가 다르다" 검사는 그대로 통과해야 한다.

## 🟡 B5. 참가자 내 설계라 **상대적** 경험을 잰다

세 조건을 한 세션에서 모두 겪으므로, 참가자는 긺 조건을 **기억 속의 즉시
조건과 대조해서** 평가한다. 대화 6개가 끝날 무렵에는 각 조건을 두 번씩
겪은 상태다.

이것 자체는 설계 선택이고 검정력에 유리하다. 다만 **"17초를 절대적으로
어떻게 경험하는가"가 아니라 "1.5초와 나란히 놓았을 때 17초를 어떻게
경험하는가"를 재고 있다.** 논문의 주장 범위를 그렇게 좁혀 써야 한다.

# C. 빠진 것

## 🟢 C1. 분석 모형이 명시되어 있지 않다

`analysis/10 §8`은 결과 절의 **순서**만 정해 두었고 모형이 없다.
사전 등록을 하든 안 하든, 데이터를 보기 전에 정해야 한다.

최소한 아래를 적는다.

- 참가자 임의 절편을 둔 **혼합효과 모형** (관측이 참가자 내 6개이므로)
- 고정효과: 지연(3) × 맥락(2) × 집단(2), 그리고 **대화 위치**(피로·순서)
- 시간 추정은 로그 변환 또는 비율(추정/실제)로 다룰지 사전 결정
- 다중 비교 보정 방침
- 조작 실패 턴(`manipulation_ok=false`) 처리 규칙 — 이미 `analysis/10 §2`에
  5% 기준이 있으나 모형 수준의 규칙으로 옮겨 적는다

## 🟢 C2. 정서적 관여를 조건별로 귀속할 수 없다

`materials/06`은 블록당 1회다. 그런데 그 블록의 세 대화는 **지연 조건이
서로 다르다.** 맥락 조작 점검으로는 맞지만, 같은 문서가 문항 5(집중)를
"종속변인에 가깝다"고 쓴다. 조건별로 나눌 수 없는 값을 종속변인으로
쓸 수는 없다.

**권고**: 문항 5(집중)를 **조건별 설문으로 옮긴다**(1문항 추가).
나머지 1~4는 블록당 1회로 유지한다.

# D. UI 검토

실제로 구동해서 모든 화면을 확인했다.

### 통과

- 참가자 화면에 **속도·지연·조건 라벨·진행바·경과 시간이 전혀 없다.** 자동 검사로도 확인
- 대기 표시는 정적 `…` 하나. 세 조건에서 동일하고 남은 시간을 암시하지 않는다
- 진행 표시 `(n / 5)`가 **전송 직후** 증가한다 — 지연 구간에 멈춰 있지 않다
- 대기 중 입력이 잠긴다 → 이중 전송이 막히고 `next_input_start_ts`가 깨끗해진다
- 본문 17px, `prefers-reduced-motion` 대응, 모든 입력에 레이블
- Enter 전송 동작

### 고친 것

- **리커트 척도의 숫자 라벨이 14px · 대비 4.23:1로 WCAG AA 미달이었다.**
  참가자가 응답하려면 반드시 읽어야 하는 요소다. 15px · `--ink-2`로 올리고
  `--ink-3` 토큰을 한 단계 진하게 바꿨다 → 미달 0건.

### 기록해 둘 설계 선택

- **대기 중 입력 잠금은 실제 챗봇과 다르다.** 실서비스에서는 기다리는 동안
  타이핑할 수 있다. 통제(이중 전송 방지, 응답 지연 측정 보호)를 위해
  생태학적 타당도를 일부 포기한 것이므로 **방법 절에 적는다.**
- 물리 카드는 블록 내내 책상에 있지만 화면에서는 한 줄 요약으로 대체된다.
  의도된 대응이며 두 맥락에서 형식이 같다.
